# 故障排查与停用

[安装步骤](../README.md) · [使用手册](USAGE.md) · [实机验证记录](VALIDATION.md)

| 现象 | 先检查什么 |
| --- | --- |
| 模块已安装，但按键照常触发系统动作 | 在 LSPosed 确认框架支持 API 102，勾选**系统框架**（`system`），重启平板。在 HyperKey 展开「运行状态与使用说明」查看本次启动的系统拦截状态。仅重开应用不会重载系统 Hook。 |
| 通用页面有开关，专属键盘的「键盘快捷键」却缺少项目或不同步 | 确认同时勾选**设置**（`com.android.settings`）和**系统安全组件**（`com.miui.securitycore`）。后者承载原生快捷键编辑页。调整作用域后重启，从 HyperKey 首页分别打开两处核对同一个全局单项。 |
| 系统设置能改，应用名单或映射却提示无法写入 | 编辑器在 HyperKey 自己的进程内。对安装 HyperKey 的用户执行[安装步骤](../README.md)中的 `pm grant` 命令，再打开编辑器。 |
| 开关变灰；或者只在某个应用里与页面显示不符 | 检查「关闭所有系统快捷键」是否开启；打开时单项保留但不可改。两个系统页面显示的是全局默认值，前台应用的覆盖规则只在运行时生效。暂停该应用的配置可与全局结果对照。 |
| 改了映射后旧组合仍能触发动作 | 映射会新增触发方式。若只需新组合，在全局或相应应用中关闭旧系统单项。若新组合也无效，检查总禁用、目标应用的焦点及是否已有相同来源的应用映射。 |
| 测试页收到 Win，远程系统不响应 | 给实际获得焦点的远程客户端启用「Win 原始按键透传」，点入远程会话，并检查客户端的键盘捕获/转发选项。测试页只能证明本地应用收到了事件。 |
| 测试页按 Win 仍打开平板任务栏 | 确认已安装含测试页修复的 0.2.0 或对应源码构建，并在安装后重启过平板。用实体键盘在测试页核对按下和松开；普通页面上的 Win 行为由该页面的规则决定。 |
| `adb install -r` 报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 已安装的包和新包签名不同。GitHub 0.2.0 正式版升级到 0.3.0 即属于此情况；换电脑自建的调试包也可能如此。参见[升级说明](../README.md#兼容性与下载)。优先用原来的签名重新构建。若决定卸载再装，先记下需要保留的配置；卸载会清除应用私有数据，重新安装后再检查授权及作用域。 |

## 停用、恢复与撤销权限

- **只想暂时恢复某个应用的行为：** 在「应用名单」暂停其配置，它将重新继承全局选择和映射。无需删除规则。
- **想恢复系统快捷键：** 先关闭总禁用。若要允许全部全局单项，在首页使用「恢复默认开关」；这会启用系统对应的快捷键，保留自定义组合键，不是恢复安装前的单项快照。若要回到自己以前的选择，请逐项改回。
- **停用模块：** 在 LSPosed 关闭 HyperKey 后重启。此后不再加载按键拦截或设置界面扩展。此前同步给小米原生快捷键库的单项仍可能保留，可在原生编辑页调整。
- **仅撤销独立应用的写权限：** 执行以下命令。这不会删除配置，也不能代替在 LSPosed 中停用模块。

  ```sh
  adb shell pm revoke io.github.hyperkey android.permission.WRITE_SECURE_SETTINGS
  ```

仍无法定位时，按[贡献指南](../CONTRIBUTING.md)提供固件版本、键盘型号、具体按键、在哪个页面操作，以及实际发生了什么。

**0.3.0 的启动/命令目标没有动作：** 检查设备已解锁、总禁用已关闭、对应名单已启用，且没有更高优先级的 Win 原始透传。应用更新或卸载后，请重选启动入口；公开 Activity 也可能要求应用提供专用参数。普通模式没有 ADB shell 权限。Root 模式需在 Root 管理器中向 HyperKey 授权，授权被拒或超时后不会自动重试执行。清除 HyperKey 的应用数据后，需重新保存自定义动作。
