## 双向同步和实体按键

1. 在 HyperKey UI 开启“回到桌面”。共享配置变为 `1:43ef:0`，系统原生 type=4 的 enable 变为 true；专属原生页面的对应开关显示开启。
2. 对 `/dev/input/event7`（经 getevent 确认为 Xiaomi Keyboard）注入 Meta+D，正确附带 MSC_SCAN、SYN 与抬键。前台从专属快捷键 Activity 变为小米桌面。此处未使用被模块排除的虚拟 `input keyevent` 来声称实体键盘验证成功。
3. 在专属原生页面关闭该项目。共享配置恢复 `1:43ff:0`，HyperKey UI 对应开关关闭；重复实体设备节点注入，前台仍是专属快捷键 Activity。
4. 通用键盘页面显示相同的关闭状态。在该页面开启 HOME，再打开总禁用，配置为 `1:43ef:1`。原生 HOME 仍保存为 true，但页面单项开关变灰不可操作。Meta+D 不返回桌面。
5. 在通用页面解除总禁用，配置恢复 `1:43ef:0`，再次 Meta+D 成功返回桌面；HyperKey 单项仍为开启。
6. 在 HyperKey 关闭 HOME，恢复测试前的 `1:43ff:0`。比较系统 `/data/system/miuishortcuts.xml` 与测试前备份，内容完全相同。

## 验证边界

以上证明 HOME 的双向同步、两个系统入口、总禁用和恢复链路有效。其他快捷键的 Hook 安装和配置覆盖已检查，尚未逐项验证全部快捷键的实际视觉行为。未在其他固件、多用户、所有键盘布局或全部自定义应用组合键上进行完整实测。

原生列表更新只在内容指纹变化时通知界面，避免原生控件绑定过程中重复保存引发刷新循环。原生单项修改保留组合键及自定义标记，使用系统自带 MODIFY 接口，没有直接替换系统配置文件。

## 0.2.0 实机验证

- Xiaomi Pad 8 Pro：API 102 已加载 29 个系统 Hook。构建和 17 项单元测试通过；最终 lint 为 0 错误、18 个警告、2 个提示。
- 实体键盘输入节点：全局禁用和仅应用启用 Win 透传两种方式下，测试页均收到 Win、D 的完整按下/松开事件和 Meta 修饰位。全局 HOME 单项禁用时，应用覆盖为允许可执行桌面动作；总禁用优先。没有连接远程会话验证远端结果。
- D → Esc 产生 Esc 的 DOWN、UP；Caps Lock → 左 Ctrl 后按 C，应用收到带 Ctrl 修饰的 C 及修饰键松开。应用 D → HOME 能返回桌面；总禁用时，同一来源传回原始 D。全局 D → Esc 与应用 D → Tab 并存时，应用收到 Tab。
- 完成英文、浅色、深色、紫色强调色和手动 HEX 应用检查，应用选择列表显示各自图标。新版映射页实机录入 D 并分别预览 Esc 和桌面动作。Material 色板 700 档蓝色色块正确填入 #1976D2，预览未修改已保存偏好。
- 键帽页实机显示 D（Android 键值 32、Linux 扫描码 32）的按下和松开。测试结束后配置已恢复。系统原生快捷键 XML 与此次测试前逐字节相同。
- 加载修复后的系统端（boot 22，29 个 Hook）：保持全局 19 项开启。测试页单击、双击、长按 Win 和 Win+D 均保持焦点并收到对应事件，Win+D 键帽显示 Win=117、D=32；离开到模块主页后 Win+D 正常返回小米桌面。通用键盘与小米专属键盘页均可打开应用名单。
- 新外观页验证：选择壁纸色后保存为动态取色；直接输入 `2196F3` 并应用后规范化为 `#2196F3`，测试后恢复原偏好。
- 标题栏左侧为无底色的返回箭头，包含中英文无障碍标签和 48 dp 点击区域。在平板实点按键映射、语言与外观、按键测试、名单、选择应用和名单编辑共六个界面的同一位置，均返回正确层级；名单与映射数据保持不变。

## 0.3.0 本地回归与待实测项

本版的本地用例覆盖总禁用对普通按键和已知组合的区别、透传 Win+D 先松 Win 的配对、暂停/删除名单回退、修饰位、旧映射与本地动作引用共存。命令用受控子进程测试授权成功、拒绝、未安装 su、超时、授权等待期间取消，以及普通命令退出码。这些用例不等同于 Android Root 管理器实测。

本次 ADB 无已连接设备。下面是新构建的真机验收项，均未标记通过：

1. 全局配置 `Win+D → Esc`，仅对一个远程客户端开启原始 Win 透传；验证本地普通应用收到 Esc，远端真实会话收到 Win+D，并先松 Win 再松 D。

4. 总禁用期间检查普通打字、音量、亮度与锁定键，复核 OEM 同步未就绪时名单与映射仍可用。更换 Android 用户后确认不会访问另一用户的目标。
